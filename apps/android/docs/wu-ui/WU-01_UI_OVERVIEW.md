## 1. 项目定位与设计目标

- **产品**：「时宜」（ShiYi），面向大学生的 AI + 智能穿戴健康生活陪伴 Android 应用。
- **核心闭环**：了解状态 → 提供选项 → 用户行动 → 反馈调整。首页负责低负担地展示状态，具体操作在相应模块完成。
- **关注领域**：睡眠、运动、饮食、情绪和日程；具体功能优先级仍由团队确定。
- **UI 语言**：简体中文；风格简洁、留白充足、信息层次清晰。
- **视觉方向**：艺术化自然风景与四季物候结合；突出“时宜”的时间感与轻量陪伴，而不是医学仪表盘或纯养成游戏。
- **医学安全原则**：避免以单次数据制造焦虑；不以 UI 推断诊断、治疗结论，不擅自放宽医学安全边界。

## 2. 当前组内讨论形成的方向

- **首页背景**：方案 A（同一棵苹果树随季节／节气变化）与方案 B（多题材的每日艺术风景）**结合探索**。具体如何结合尚未最终确认，不能据此直接实现某种切换规则。
- **宠物交互**：移入独立的宠物陪伴板块，**首页不展示互动宠物**。
- **首页信息密度**：大面积风景为主，保留少量健康摘要（如今日步数／活动量、心率）。
- **已提出的精简偏好**：不放“今日时宜”大建议卡；不放与底部导航重复的“计划”快捷卡；底部导航倾向仅图标；不自行绘制手机 Wi-Fi、电量等系统状态栏。
- **动态背景**：当前阶段暂缓设计与开发，先评估静态背景体验。

## 3. 页面及导航：存在架构差异，待团队协调

- UI 讨论中曾提出“首页／健康／计划／陪伴”的四个导航入口，底部仅用图标呈现。
- **当前仓库 README 中 Android 起点是“今日／四时／探索／我的”**，属于现有项目结构；两者并不一致。
- 本文仅记录 **UI 候选信息架构**，不要求其他成员修改现有导航、Compose 路由或功能模块。
- 宠物板块是否整合进“陪伴”入口，以及它与 AI 对话页面的关系，仍需组内决定。
