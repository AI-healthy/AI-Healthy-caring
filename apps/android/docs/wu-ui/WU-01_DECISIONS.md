# 时宜 App · UI 设计状态、变更与待决定事项

> 更新：2026-11-19  
> 本文件是**个人 UI 需求讨论记录**，不替代团队批准的 ADR／项目知识库正式决策。  
> 本人工作范围：`apps/android/docs/wu-ui/`，只在个人分支 `feat/wu-season-ui` 提交。

## A. 当前已明确的原则／方向

| 主题 | 当前描述 | 状态 |
| --- | --- | --- |
| 视觉风格 | 简约、自然、艺术化、简体中文 | 设计方向 |
| 首页背景 | 方案 A 四季苹果树＋B 艺术风景 **结合探索** | 已形成组内方向，细节待定 |
| 植物变化 | 随自然日期／季节／节气，而非健康表现与任务 | 个人明确原则 |
| 宠物位置 | 独立陪伴板块；首页不放虚拟宠物 | 组内讨论方向 |
| 虚拟角色 | **Stack-chan**；此前布偶猫作为主角色不再采用 | 用户近期明确选择 |
| 首页精简 | 无“今日时宜”大卡、无重复计划快捷卡 | 个人明确偏好 |
| 静态素材 | 动态油画暂缓 | 当前设计范围 |
| 画面与 UI | 不把导航、文字、状态栏直接烘焙入背景 | 设计原则 |

## B. 最新初步选择（尚未团队正式定稿）

| 主题 | 当前候选倾向 | 待验证 |
| --- | --- | --- |
| A＋B 结合方式 | **固定苹果树＋变化艺术背景**，而非简单双模式切换 | 分层素材、画风与光影一致性 |
| 健康内容 | 睡眠、运动、饮食、情绪 **四模块均设计** | 首版技术实现范围另定 |
| AI 建议入口 | 主要在独立 AI 对话页面 | 其他页面是否留捷径 |
| 陪伴与 AI | 在陪伴页点击 Stack-chan 进入对话 | 角色资源及交互细节 |
| 首页三环 | 仅三个同心圆环，默认不显示数字，点击进入健康页 | 位置、大小、空状态、是否实际采用 |
| 圆环指标 | 用户可从合适的活动类可用数据中自定义三个 | 必须存在有效目标和授权；不将心率当完成率 |
| 页面滚动 | 首页／陪伴固定；健康和计划滚动；AI 消息滚动且输入固定 | 短屏与无障碍适配 |
| 图片图库 | 用户接受现有 30 张总体视觉风格，可继续扩充 | 正式资源统一构图和清晰度 |

## C. 需求演化：保留历史，避免旧文档误导

1. 初期：首页机器人、大“今日时宜”卡片、健康／计划双快捷入口。
2. 后期：首页机器人取消，动物桌宠提出后移至独立板块。
3. 健康展示经历“显示数据摘要 → 全部从首页移除 → 重新讨论小型三环”的变化。**当前仅三环是候选**，不能误写为恢复首页详细健康数据。
4. 宠物主形象从布偶猫调整为 Stack-chan；传统宠物喂食、梳毛等不作为默认计划。
5. A 与 B 从相互竞争的两种背景方案转为结合探索；当前倾向树与背景图层融合，但未经团队最终批准。
6. 图片已用于概念筛选，但不代表 Figma 高保真稿或 App 界面功能已完成。

## D. 当前素材与 GitHub 范围

- 30 张候选图：苹果树 A 组 12 张高分辨率独立图，风景 B 组 18 张从概念展示板裁切的预览；两组质量等级不同。
- 原始素材留在外接硬盘素材库／对话导出包；GitHub 只提交必要的个人文档、素材清单及少量压缩预览。
- 仓库主分支当前 Android 导航仍以“今日／四时／探索／我的”呈现；个人 UI 的“首页／健康／计划／陪伴”只是候选架构，不强制修改其他人的源码。
- 图片、交互、健康数据和硬件连接均不得标记为已开发完成。
