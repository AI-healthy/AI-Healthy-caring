# 时宜 App · Stack-chan 陪伴与 AI 对话（UI 讨论稿）

> 更新：2026-11-19  
> 状态：**采用 Stack-chan 作为虚拟陪伴的设计选择；具体功能、资源与开发仍待评审**  
> 范围：仅 App UI／交互；不修改实体机器人固件或接口。

## 1. 角色位置与历史变化

- **首页不放虚拟角色。** Stack-chan 位于独立的「陪伴」板块（具体导航栏目与团队架构待协调）。
- 近期明确选择 **Stack-chan 机器人形象**，取代此前布偶猫／动物桌宠作为主要角色。
- 历史候选中的喂食、梳毛、动物饥饿值和惩罚性养成不再作为默认功能。
- App 内的虚拟 Stack-chan 与团队探索的**实体 Stack-chan**是两个交付边界；同形象不代表已经实现硬件同步。

## 2. 推荐 UI 流程（待组内确认）

1. 进入「陪伴」：Stack-chan 主体居中，少量触摸／表情交互；整屏固定，不滚动。
2. **点击 Stack-chan 进入独立 AI 对话页面**（用户本轮倾向），AI 对话页保留返回路径。
3. 聊天消息滚动、底部输入固定；支持文字输入、快捷问题候选、对话历史入口。
4. AI 可提出可以调整／拒绝的行动选项；经用户确认后才加入「计划」。
5. 使用健康／日程数据前需向用户展示授权与数据范围；无授权时允许普通对话。

## 3. 功能候选分级（设计优先级，不是研发承诺）

| 功能 | 候选级别 | 说明 |
| --- | --- | --- |
| Stack-chan 角色与点击进入 AI 对话 | 优先原型 | 核心入口 |
| 简单待机表情／点击反馈 | 优先原型 | 控制动态干扰 |
| 历史对话、快捷提问、建议卡片 | 优先原型 | 位于 AI 对话页 |
| 简单点头、屏幕表情主题 | 后续候选 | 需要可用角色资源 |
| 长按拖拽、语音对话 | 后续候选 | 需交互与技术评估 |
| 连接实体 Stack-chan、表情或语音同步 | 技术验证后评审 | 不宣称已接入 |
| 商店、复杂养成、惩罚式宠物数值 | 暂不建议 | 不符合低负担陪伴原则 |

## 4. 素材、许可与体验边界

- 拟使用 Stack-chan 形象须核对对应开源项目／图形素材的使用许可、署名和二次创作约束；不能只凭名字认定所有图片均可直接商用或再分发。
- 生成的概念角色图不能视为官方素材，也不能直接宣称能在实体硬件上实现。
- 避免以机器人的表情推断用户疾病／情绪诊断；AI 不自动替用户修改健康目标或强制添加日程。
- 首阶段仅开展 Figma 静态／可点击交互设计，未完成机器人驱动与 AI 接口联调。

## 5. 待讨论
