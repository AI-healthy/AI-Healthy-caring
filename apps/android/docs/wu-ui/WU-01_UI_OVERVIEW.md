## 1. 产品与 UI 定位

- 产品暂名「时宜」（ShiYi），面向大学生的 AI＋智能穿戴健康生活陪伴 App，目标平台 Android。
- 用户体验闭环：了解状态 → 提供选项 → 用户选择／行动 → 反馈调整；该闭环是产品目标，不代表技术链路全部实现。
- 健康相关规划覆盖 **睡眠、运动、饮食、情绪**；计划管理负责执行与反馈，Stack-chan 引导进入独立 AI 对话。
- 简体中文、简约清晰、适度留白；首页采用艺术化风景呈现自然时间的流逝。
- 医学安全：不把数据可视化包装成诊断，不根据画面推断风险；AI 不自行放宽安全边界，避免制造健康焦虑。

## 2. 页面架构（待团队评审）

| 一级页面（UI 候选） | 页面主要职责 | 推荐滚动方式 |
| --- | --- | --- |
| 首页 | 日期／节气、苹果树＋可变化艺术风景、可选三环活动组件 | **固定整屏** |
| 健康 | 睡眠／运动／饮食／情绪四个入口及各自详情 | 总览和详情纵向滚动 |
| 计划 | 日程、任务、用户确认后的 AI 建议、完成／跳过与反馈 | 日期横向切换、任务列表纵向滚动 |
| 陪伴 | Stack-chan 主体、轻量互动、点击角色进入 AI 对话 | 优先固定整屏 |
| 独立 AI 对话（二级页） | 提问、可选择建议、确认加入计划 | 消息滚动，顶部及输入区固定 |

- 个人中心、设备／授权、通知、背景偏好、无数据与离线状态属于辅助设计范围。
- 底部四个图标的具体栏目 **未与开发架构达成一致**：团队仓库 Android 当前写“今日／四时／探索／我的”。不得由本讨论稿直接要求改写既有路由。
- Stack-chan 虚拟角色不出现在首页；实体 Stack-chan 开发是另一工作流，不因 UI 位置变化而取消。

## 3. 首页当前方向及时间顺序

- 组内方向：方案 A（固定苹果树的季节物候）与 B（多题材艺术风景）结合探索。
- 个人近期倾向：**固定苹果树＋变化背景的同画面融合**；仍是待团队确认的实现方式。
- 树的变化只跟自然时间／节气有关，不与用户睡眠、运动、任务或登录频率绑定。
- 保持首页极简：不放“今日时宜”大建议、不放重复的“计划”快捷卡、不放 Stack-chan。
- **健康信息经历两次调整**：曾设想首页健康摘要 → 一度完全移除 → 最新重新讨论**默认只显示三层活动进度圆环**，不直接展示步数／心率／睡眠数字；点击圆环进入健康页面看详情。三环具体形态与指标仍为**候选需求**，不当作定稿。
- 本阶段只制作静态背景；动态油画暂缓。

## 4. 健康、计划与 AI 的分工

- 健康：查看和手动补充适当记录，提供数据来源与更新时间，涵盖睡眠／运动／饮食／情绪。
- 计划：用户编辑任务，接收**已确认**的 AI 建议，记录完成／跳过／调整及反馈。
- AI：主要由点击陪伴页 Stack-chan 进入独立对话页。对话中可以提出可拒绝、可调整的建议；读取个人健康／日程信息应先取得适当授权。
- Stack-chan：以现有开源机器人形象作为虚拟陪伴设计方向；首轮仅设计视觉、点击对话和简单表情反馈，不声称已有真实控制或硬件联动。
